# 一页 · 中文 TXT 阅读器

面向对象程序设计课程第一版 MVP。原生 HTML、CSS、JavaScript 实现；书籍保存在本机浏览器。支持多书书架、UTF-8 / GB18030、滚动阅读、字号、浅色和深色主题，以及每本书独立的阅读位置。

## 打开程序

当前电脑已检测到 Node.js 和 Python。最方便的方法：双击项目中的 **启动阅读器.cmd**，等待浏览器打开。保持出现的终端窗口运行，阅读结束后在终端按 `Ctrl+C` 停止，再关闭窗口。

也可以在本项目文件夹打开 PowerShell，输入：

```powershell
npm start
```

浏览器访问：<http://127.0.0.1:8000/>。运行阅读器无需 `npm install`；启动服务只使用 Node.js 内置模块。

若电脑没有 Node.js，但有 Python，可以改用下面的命令，随后访问相同地址：

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

两种服务只需运行一个。端口被占用时，先检查已有页面和终端；关闭旧服务后再启动。阅读器通过本地 HTTP 服务打开，JavaScript 模块由浏览器加载。

## 五分钟动手测试

1. 打开页面，保持默认 UTF-8，点击“导入 TXT”，选择 `samples/河边散记-UTF8.txt`。应显示正常中文，左侧出现一本书。
2. 向下滚动，等待底部显示“已保存”。在阅读区域顶部调整字号、切换深色主题；这组按钮会随阅读保持可见。
3. 将编码改为 GB18030，导入 `samples/山间来信-GB18030.txt`，滚动到另一位置。
4. 点击左侧第一本书，再点击第二本书，两本书应分别回到各自的位置。
5. 等待“已保存”或“阅读设置已保存”，刷新页面，再关闭标签页并重新访问相同地址；应保留书架、最近一本书、字号、主题和阅读位置。
6. 点击一本书的“删除”，先取消一次，再确认一次；只有确认后才从书架消失，原始 TXT 文件保留。

## AI 辅助阅读

打开一本书，选中正文，点击“✦ AI 解释”。阅读器会将书名、选文和附近正文发给 DeepSeek；模型参考书名对应的已有知识和提供的原文，未使用联网搜索。书名可能不准确，模型对书的了解也可能有误。回答下方可继续提问，当前页面会保留对话，切换书籍、重新选文、改变剧透选项或关闭页面后清空。

默认发送选文前最多 5000 个字符和选文；勾选“允许使用选文之后的内容”后额外发送后文最多 1500 个字符。默认要求模型避免剧透，模型仍可能根据已有知识意外透露情节。每次解释或追问都会发送相关文字并可能产生费用。旧版分析生成的摘要不会被使用，原本存储的数据暂时保留，删除对应书籍时一并删除。

### DeepSeek 本机配置

使用此功能需要 Node.js 20 或更新版本、网络及有调用额度的 DeepSeek API 账户。请在 [DeepSeek API 平台](https://platform.deepseek.com/) 创建自己的 API Key，启动阅读器，打开一本书后点击“AI 助手”，在弹窗中输入密钥。也可以选中文字后点击“AI 解释”，首次使用时同样会显示配置窗口。

密钥只保留在当前网页内存，刷新或关闭页面后需要重新输入。AI 面板中的“更换密钥”可更换当前密钥。每次请求会把密钥发送给本机阅读器服务，再由服务请求固定的 DeepSeek 官方接口；不要将密钥发到聊天里。使用 AI 时按输入和输出 token 计费，每次点击或重试可能产生费用。价格与账户额度以 [DeepSeek 官方定价](https://api-docs.deepseek.com/quick_start/pricing/) 为准。

AI 功能需要本项目的 `npm start` 或启动脚本；Python 静态服务只能使用基础阅读功能。

乱码时切换编码并重新导入原 TXT。错误编码导入形成的条目可手动删除。书名相同的导入会作为两本独立书籍保留。

## 代码怎样对应面向对象知识

- `Book`：一本具体的书；属性记录书名、段落和位置，方法约束位置范围。
- `TxtImporter`：负责把文件变成书籍对象，集中处理编码与格式检查。
- `LibraryStore`：负责数据库读写，封装 IndexedDB 的事务细节。
- `ReaderSettings`：管理字号、主题和设置持久化。
- `ReaderView`：负责显示内容、书架和状态，以及获取与恢复阅读位置。
- `ReaderApp`：组合上述对象，协调用户操作。`main.js` 创建应用对象并启动。

建议先看 `Book.js`，再沿着 `ReaderApp` 的导入流程看对象如何协作。课程讲解重点是类与实例、属性与方法、封装和组合。所有正文通过纯文本方式显示。

完整功能与设计见 [开发文档](开发文档.md)。

## 使用范围与已知限制

- 单本原始 TXT 上限 5 MiB；超长文本使用完整 DOM 渲染，未进行大规模性能测试。
- 数据属于当前浏览器和当前地址。固定使用 `http://127.0.0.1:8000/`；更换端口或浏览器会使用另一份数据。
- 清除网站数据或浏览器回收存储可能删除书架，请保留原 TXT。隐私模式不适合长期保存。
- 推荐一个标签页使用阅读器；多标签页同时修改同一本书时，最终以最后写入的位置为准。
- 滚动每约 500 ms 保存，立即强制关闭可能丢失最后一小段位置。字号和窗口变化后允许少量定位误差。
- 不含云同步、章节识别、搜索、批注或 PDF / EPUB 支持。

## 云端书架（测试项目）

左侧“云端书架”可使用邮箱和密码注册、登录。首次使用需在窗口中填写 Supabase Project URL 和 Publishable key（或 anon key），不要填写 secret key、service_role 或数据库密码。当前测试项目已创建私有 `reader-books` 存储桶、书籍表、进度表及访问规则；不要重复运行数据库脚本。当前项目关闭邮箱确认，注册不发送确认邮件，邮箱归属未经验证；应用暂不提供自助找回密码，适合受控的课程演示。密码至少 8 个字符。

登录后点击“打开云端书架”，上方“导入 TXT”上传到当前账号；切换到本地书架可继续使用原有浏览器数据。需要迁移本地书籍时，在云端窗口选择“选择本地书籍迁移”，勾选并确认上传；原本地书籍仍保留。云书与本地书架分开，个人 TXT 应保留原文件。

滚动后进度同步，页面显示“已同步”代表服务端已确认；断网时会显示失败并提供重试。发生双设备冲突时，可选择云端进度或保留本机进度。删除云书会删除对应云端正文及进度。请在共享电脑使用后退出登录，注意浏览器可能保留待同步数据。

另一台设备需要获得此项目代码并安装 Node.js，启动 `npm start`，访问该设备自己的 `http://127.0.0.1:8000/`；在其浏览器填写同一项目的公开 URL 与 Publishable key，用同一账号登录。当前服务只监听本机，未公开部署；两台设备需联网访问 Supabase，不能用一台设备的 `127.0.0.1` 直接访问另一台。阅读设置按设备保存；AI Key 需在每个浏览器页面会话中单独输入。

2026-11-10 使用随机测试账号和自编文本完成真实 Supabase 测试：注册登录、两账号书籍与进度访问隔离、上传下载和删除、独立浏览器会话恢复进度、进度冲突与幂等、断网提示及恢复后重试。测试文本已删除；随机测试账号仍在 Supabase Auth。两台实体设备之间的访问未实测。云书选文与 AI 面板使用模拟模型响应测试，未进行真实 DeepSeek 调用。请勿把这些结果理解为已完成公开部署或生产环境安全审计。

补充：已在隔离浏览器中用自编本地书籍验证勾选并确认迁移；删除云端副本后，原本地书仍保留。
